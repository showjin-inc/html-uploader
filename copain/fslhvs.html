1ヒアリング・面談の日程確定で Google Meet の URL を自動発行 新機能

これまでは通話 URL を用意するために、先に自分でカレンダーへ Meet 付きの予定を作り、その URL を確定フォームに貼り付ける 必要がありました。確定操作でさらに予定が作られるため、カレンダーに予定が二重に並ぶ状態でした。今回から 日時を選んで確定するだけ で Meet の URL が発行されます。

企業ヒアリング（依頼詳細 → 企業ヒアリングタブ）では、通話URLの入力欄が既定で表示されなくなりました。「Google Meet を自動発行します」と表示されるだけなので、日時を選んで確定するだけ で完了します。担当オペレーターのカレンダーに Meet 付きの予定 が作られ、発行された URL がそのまま依頼者への通知メールと画面に入ります。

Zoom など別の URL を使う場合は、「別の通話URLを使う（Zoom 等）」にチェック を入れると入力欄が表示されます。手入力した場合は Meet を発行せず、その URL を使用します（チェックを外すと入力値がクリアされ、Meet の自動発行に戻ります）。

スタッフ面談 でも同じように Meet を自動発行し、発行された URL はスタッフ詳細の面談予定日時の横に表示されます。

あわせて、タスクボードのスケジュール（本日／明日／明後日以降／期限超過）の各カードに 「Meet に参加」リンク を追加しました。企業ヒアリング・スタッフ面談のどちらも、予定の時間になったらボードから直接入室できます。

  • 担当者の Google カレンダー連携が前提です。連携していない場合や「カレンダーに予定を追加する」を外した場合は、従来どおり通話URLの手入力が必要です。
  • 日時を変更して再確定すると予定を作り直すため、Meet の URL も新しくなります（新しい URL で依頼者へ再通知されます）。手入力した URL は再確定時もそのまま引き継ぎます。

2空き時間の判定を実態に合わせて見直し（前後30分・終日予定） 修正

ヒアリング・面談の空き時間表示について、実際には予定を入れられない時間帯が「空き（○）」と表示される 2つのケースを修正しました。

1つ目は 前後の準備・後処理時間 です。予定を登録すると本予定の前後に30分の準備・後処理予定も作られますが、空き判定が本予定の時間しか見ていませんでした。たとえば 12:00〜13:00 に予定がある場合、13:00 の枠は空きに見えても、登録すると準備予定（12:30〜13:00）が既存予定と重なってしまいます。前後30分を含めて判定 するよう修正しました。

2つ目は 終日予定 です。Google カレンダー側の仕様で終日予定は「予定なし」として扱われることが多く、お盆休み・休業日などを終日予定で入れていても空きと表示 されていました。今回から終日予定も予定ありとして扱い、その日は終日「×」 になります（複数日にまたがる終日予定は全期間が対象）。

  • キャンセル済みの予定、ご自身が「欠席」で回答した予定は空き判定に含めません。
  • コパン（依頼者）側のヒアリング希望日時の選択画面、ShowCase 側の日時確定画面・スタッフ面談の日程調整、いずれにも反映されます。

3スタッフ面談の予定を、どの画面から登録してもカレンダーに反映 修正

スタッフの面談予定日時は 4つの画面（スタッフ詳細のステータス編集／登録ボードの面談予定への移動／スタッフの新規登録／スタッフ編集）から設定できますが、カレンダーへ予定が作られるのはスタッフ詳細のステータス編集からのみ でした。登録ボードから面談予定に動かした場合などは、面談日時が保存されるだけでカレンダーには何も入らない状態でした。

今回から どの画面から設定してもカレンダー予定（本予定＋前後30分の準備・後処理）が作られます。面談担当を「未割り当て」に戻したり面談予定を消した場合は、作成済みの予定と通話URLもあわせて片付けます。

4条件変更見積もりの通知を追加（依頼者メール・回答の Slack 通知） 新機能

条件変更見積もりの進行について、これまで通知がなく 依頼者へは個別にご連絡いただく必要 がありました。通常の見積もりと同じように、依頼者向けメール と Slack 通知 を追加しました。

依頼者へのメールは、ShowCase 側の操作に合わせて 4種類 送信されます。「この内容で提示する」（提示）／「企業同意としてマーク」（同意の受付）／「辞退としてマーク」（辞退の受付）／「取り下げ」 です。内容の修正だけを保存した場合はメールは送信されません。

文面は 詳細設定（コパン）の「通知メール文面」タブ で編集できます。件名・本文の編集、送信の ON／OFF、既定の文面へのリセットが、既存の通知メールと同じ操作で行えます。

Slack へは 条件変更見積もりへの回答（同意／辞退） が届きます。ON／OFF は詳細設定（コパン）の連絡先タブの一覧で切り替えられます。1件に同意すると他の見積もりが自動で辞退扱いになりますが、その自動辞退は通知しません（1回の回答で通知が何件も飛ばないようにしています）。

  • 依頼者がポータルで自分で同意・辞退した場合は画面で完結するためメールは送らず、Slack で運営へお知らせします。

5タスクボードの停滞理由を「フェーズ」と「担当」で表示 改善

「停滞している依頼」カードの表示を分かりやすくしました。従来は停滞日数だけの表示（例:「7日停滞」）で どのフェーズで止まっているのか分からず、また 自分のタスクとして出ている理由 も判別できませんでした。

今回から各行に 止まっているフェーズ名（人選中・見積完了 など）と、誰のボールか（オペ／営業／企業）のバッジを表示します。企業側の回答待ちであれば「企業」バッジと「◯日待ち」で表示されるため、催促が必要なのか自分が動くべきなのかが一目で分かります。

また、同じ依頼が複数の条件で停滞している場合（例: 人選中の停滞と条件変更見積もりの回答待ち）、従来は理由ごとに別の行になり、日数順に並ぶため離れた位置に表示され、件数が多いと片方が埋もれていました。今回から 依頼ごとに1行へまとめ、停滞理由をすべて並べて表示 します。

  • あわせて、「派遣中」の判定が派遣終了日を見ておらず、期間が終了した後も派遣中のままだった点を修正しました。

6顧客へ送付した提案内容を、選考が進んだ後でも確認できるように 改善

候補スタッフの提案内容（コパンからのおすすめポイント・提案時の希望条件）は 「受け入れ確認中」のあいだしか表示されず、見送り・現場見学調整・決定などに進むと 何を提案したか確認できない 状態でした。

今回から、スタッフ選考タブの各候補カードに 「顧客へ送付した提案内容」の折りたたみ を追加しました。選考ステータスに関係なく、いつでも開いて おすすめポイント・居住地エリア・就業希望日数・勤務可能期間・勤務可能な曜日／時間・希望雇用形態・経験年数・経歴・スキル・交通費・履歴書の添付有無 を確認できます。

  • 「受け入れ確認中」の候補は従来どおり、提案情報を常時表示します。
  • 提案前（打診・エントリー直後）の候補には表示されません。

7スタッフの就業ステータスを画面間で統一 修正

スタッフ管理の 就業ステータスが画面によって食い違う 問題を修正しました。スタッフ一覧・基本情報は保存された値を表示し、就業ボードとダッシュボードの件数は依頼側のデータから毎回算出していたため、「一覧では待機中なのに就業ボードでは派遣中」 という状態が起きていました。

今回から 一覧・基本情報・就業ボード・ダッシュボードの件数がすべて同じ判定 になります。判定は依頼側の実データを正とし、優先順位は 派遣中 ＞ 派遣決定 ＞ 職場見学予定あり ＞ 案件検討中 ＞ 非アクティブ ＞ 待機中 です。

あわせて次の点も修正しました。派遣期間が終了したアサインを「派遣中」に数えていた点、同じスタッフが就業ボードの複数の列に表示され、ダッシュボードの件数も二重に数えられていた点、一覧の絞り込み結果と表示ステータスが一致しなかった点 です。一覧の「手配（空き・稼働中・選考中）」の絞り込みも同じ判定に統一し、派遣期間が終了したアサインは「稼働中」に含めないようにしました。

8パターンのツールチップで派遣期間が正しく表示されない不具合を修正 修正

依頼詳細のスタッフ選考タブで、候補スタッフに表示される パターンバッジのツールチップ について、派遣期間が 「- 〜 -」 と表示される場合がありました。開始日・終了日を持たず 派遣期間（◯か月）だけを指定したパターン で発生していました。

今回から、「3か月（開始/終了日 未定）」 のように月数で表示します。AGENT採用の場合は 「稼働開始: YYYY/MM/DD〜（採用前◯か月）」 と表示します。

  • 候補追加時のパターン選択のツールチップと同じ内容・同じ基準（条件変更見積もり反映後の最新条件）に統一しました。従来は候補カード側が変更前の値を表示していました。

9スタッフご紹介PDFが出力できない不具合を修正 修正

スタッフ詳細の「面談内容」タブから ［PDF］（スタッフご紹介資料） を押しても、1分ほど待たされた末にエラーになりダウンロードできない 状態でした。原因は PDF の作り方で、これまでは サーバー内でブラウザを起動して HTML を印刷 していたため、ブラウザの起動だけで約 1GB のメモリを必要とし、サーバーの割り当てに収まらず時間切れになっていました。

今回、PDF の作り方を変更 しました（御見積書の PDF と同じ仕組みに統一）。ブラウザを使わず PDF を組み立てるため、0.2 秒程度で生成 できるようになり、サーバーの増強も必要ありません。

資料の内容・項目は変わりません。見た目もほぼ同じですが、次の点だけ差があります。

  • スタッフタグの折り返し位置 が変わることがあります（1行に入る個数が1つ前後）。
  • 「花業界の経験」「希望勤務条件」の枠の角が四角 になります（他の枠・タグは従来どおり角丸）。
  • タグが多い場合に 2ページに分かれず A4 1枚に収まる ようになりました（従来は溢れることがありました）。
  • 書体は従来と同じ（BIZ UDPGothic）です。

10スタッフ管理の入力エラー表示・必須項目・編集ボタンを見直し 改善

面談内容の登録でエラーになったとき、「desired employment typeは必須項目です。」のように項目名が英語で表示 されていました。項目名を日本語に整備し、あわせて一部のエラーが 「validation.after_or_equal」のような内部の文字列で表示 されていた問題も直しました。スタッフ管理以外の画面のエラー表示も読みやすくなります。

面談内容の必須項目を見直しました。これまで「希望雇用形態（エージェント用）」が必須でしたが、面談の時点では未確認のこともあるため 任意に変更 しました（面談内容で必須だった項目はこれだけです）。

スタッフ詳細の編集ボタンが分かりにくかったため、画面右上の「編集」を基本情報の枠内へ移し「基本情報を編集」 に、ステータスの編集は 「ステータスを編集」 に表記を変えました。どちらを編集するボタンなのかが分かるようになります。

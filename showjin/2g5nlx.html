コパン運用フロー

SHOWCASE 管理画面のステータスをそのまま業務手順にした、営業・オペレーション・スタッフ登録の標準フローです。「いま誰のボールか」「何日で警告が出るか」「どの画面で操作するか」を各ステップに紐づけています。

対象 笑人 コパン事業部（営業／オペレーター） 基準システム SHOWCASE（show-case.app） 作成日 2026/08/27
全体像 営業フロー オペフロー 選考サイクル スタッフ登録・就業 日次・週次の運用

00全体像

コパンの案件は「見積」と「依頼」の2つの箱で管理され、そこにスタッフプールから人を差し込む構造です。まずこの3本の線を押さえます。

案件の入口は2つあります。企業が自社ポータルから見積を出す企業発信と、営業が先回りして見積を作って提示するShowcase 発信です。どちらも「見積依頼」として立ち、企業が発注した瞬間にコパン依頼へ変わり、14 段階のステータスを進みます。

サービス種別は 人材派遣 と AGENT採用 の2つ。フローの骨格は同じですが、選考の中身が「現場見学」か「面接」かで分かれ、人材派遣だけが派遣必須情報（事業所・抵触日）と社会保険手続きを持ちます。

営業 オペ 企業（要催促） スタッフ担当 システム自動 SHOWCASE 内の色分けと同じく、赤＝運営が動くべき停滞／黄＝企業の対応待ち（＝催促する）。

01営業フロー

見積依頼 → 見積完了 → 受注依頼 → 企業ヒアリング予定。オペにバトンを渡すまでの4ステップで、ボールは営業と企業を交互に行き来します。

ステータス主担当期限やること自動で飛ぶ通知
01見積依頼 営業 2日
停滞警告		 勤務条件パターン（最大3件）ごとに請求時給・スタッフ時給を入力。最低賃金の法定下限を下回ると警告が出るので必ず解消する。粗利は自動計算。各パターンで「可／見送り」を選び、プレビューを確認してから企業へ提示。まだ詰めきれないときは一時保存。 コパン → 見積管理 → 詳細 見積回答送信
02見積完了 企業 3日
企業対応待ち		 企業の発注判断待ち。3日を超えたら営業が催促する（放置＝対応漏れ扱い）。発注されると見積が「コパン依頼化」され、依頼管理に現れる。 タスクボード → 要対応 → 企業対応待ち サービス依頼受付
03受注依頼 営業 2日
停滞警告		 受注内容タブで確定募集人数・請求時給・スタッフ時給・残業／深夜割増・派遣期間・実働時間・週日数を確定させる。ここで決めた数字がこの後の粗利と契約のベースになる。 依頼詳細 → 受注内容 → 受注内容を更新する 受注確定
04企業ヒアリング予定 営業 3日
日時未確定のみ		 日時を確定させると停滞対象から外れ、以後は期限超過（猶予0日）で管理される。ヒアリングでは1日の流れ・服装・必要スキル・職場の雰囲気・アクセス・収入例など18項目を埋める。ここの密度がそのまま求人原稿の質になる。 依頼詳細 → 企業ヒアリング ヒアリング日時確定

営業が受注後も持ち続ける仕事

バトンをオペに渡したあとも、営業は「企業と話す役」として次の4つを持ち続けます。ここが抜けると案件が止まります。

  • 現場見学／面接の日程調整と実施 ― 調整が3日、実施後の意向確認が3日で警告。
  • 採用確認 ― 見学後の確認予定日を過ぎると期限超過（猶予0日）。
  • 契約更新の意向確認 ― ⑪派遣中（更新確認中）で7日。
  • 条件変更見積もり ― 稼働中の条件変更は見積を再提示。企業回答待ち／受注確定待ちが要対応カードに出る。

受注前の必須チェック：労働者派遣基本契約書
企業単位で締結が必須です。未締結の依頼には全ステータスで⚠が出続けます。遅くとも勤務開始日までに締結し、企業・店舗管理 → 企業編集で締結年月日を登録してください（登録しないと警告は消えません）。

02オペフロー

求人掲載予定から派遣完了まで、依頼ステータス⑤〜⑭。オペが主管ですが、途中で企業と営業に3回ボールが渡ります。

ステータス主担当期限やること自動で飛ぶ通知
05求人掲載予定 オペ 5日 ヒアリングメモ＋受注確定情報から媒体別の求人原稿を生成し、媒体ごとに掲載ステータスを更新する。出力先は花JOB／フラワージョブ／CO（キャスティングワン）／Airワーク／indeed。 依頼詳細 → 求人情報出力 ―
06人選中 オペ 営業 7日
枠未確保も7日		 候補を検索して追加 →打診／エントリー→企業へ提案→受入確認→見学・面接→採用決定。詳細は選考サイクル。候補が1人もいない枠は「枠未確保 N枠」として別に警告されるので、まず埋めることを優先する。 依頼詳細 → スタッフ選考 候補スタッフ提案 / 現場見学・面接日確定 / 派遣スタッフ確定
07派遣情報確認中 企業 3日
企業対応待ち		 企業が事業所名・事業所所在地・派遣受入制限（抵触日）を登録するのを待つ。3日で催促。人材派遣のみ。 依頼詳細 → 派遣必須情報 ―
08一部手配済み オペ 7日 募集人数の一部だけ確定した状態。残枠の手配を続ける。残枠で見学が動いている間は停滞警告が抑制される。 ―
09派遣確定 自動 対象外 定員満了で開始日を待つだけの状態。停滞には数えない。開始日になると自動で「派遣中」へ。欠員が出た場合は枠未確保として検知される。 派遣開始 N日前
10派遣中 オペ 対象外 稼働中。雇用保険・社会保険の加入手続きが必要なスタッフは「保険手続き未処理」として要対応に出続ける。加入日を登録して消し込む。稼働終了時は喪失手続きも同様。 依頼詳細 → 稼働・更新 ―
11派遣中（更新確認中） 営業 7日 契約期間が60日以上なら終了30日前、59日以下なら15日前に自動で開始される。企業とスタッフ双方の更新意向を確認して確定させる。 契約更新意向確認
12派遣中（更新確認済み） 営業 オペ 対象外 更新あり→次回の依頼書（更新契約）を作成。未作成のままだと「更新契約 未作成」が要対応に出る。更新なし→終了処理へ。抵触日を越える契約は「抵触日違反」として警告。 ―
13完了確認中 オペ 5日 全アサインが終了した状態。保険の喪失手続き・実勤務日数の確定など残処理を片付ける。 ―
14派遣完了 オペ 手動 依頼詳細の「派遣完了にする」を押して確定。自動では完了しないので、⑬に溜まったまま放置されがち。週次で必ず棚卸しする。 派遣完了

03選考サイクル

⑥人選中の中身。ここが最も止まりやすく、実際に現在17件が人選中・うち10件が停滞しています。1候補ごとにフェーズと期限が別管理されます。

SEARCH

候補検索で必ず使う除外

「スタッフNGリスト対象除外」「見送り歴ありスタッフ除外」「現在稼働中を除外」「別案件で候補中を除外」「本登録のみ」。外すと二重打診や過去NGの再提案が起きます。

MATCHING

ショップ／ウエディング／葬儀の経験年数、運転可能車種（AT軽〜2tトラック）、希望勤務地、希望の働き方。配送業務がある案件は車種の確認が必須です。

SLOT

「枠未確保 N枠」＝候補も確定もいない枠の数。「枠未確保 N日」＝最後に候補が動いた日からの放置日数（7日で警告）。派遣中・派遣確定でも欠員は検知されます。

04スタッフ登録・就業フロー

依頼とは独立して回す、人材プールを育てる流れ。登録ボード（採用まで）と就業ボード（稼働まで）の2枚で管理します。

ステップ主担当やること自動で飛ぶ通知
エントリー受付 スタッフ担当 媒体からのエントリーを受け付け、登録内容の入力を案内する。仮登録のままヒアリング予定が設定されない日数が続くと登録ボードとダッシュボードに警告が出る。CSV一括取り込みも可。 スタッフ管理 → 新規スタッフ登録 / CSV取り込み エントリー受付のお知らせ / 登録内容の入力のご案内
面談日程調整中 スタッフ担当 面談日時を確定させる。確定するとタスクボードのスケジュールに載る。 面談日程確定
面談予定 → 面談実施 スタッフ担当 「スタッフ面談内容」の設問に沿って実施し、経験年数・運転車種・希望条件・タグを登録する。ここの入力精度がそのまま人選の検索精度になる。予定日を過ぎて未実施だと期限超過（猶予0日）。 ―
本登録 / 不採用・辞退 スタッフ担当 本登録にすると就業ステータス「待機中」となり、人選の検索対象に入る（候補検索の「本登録のみ」で絞られる）。 ―
待機中 → 派遣中 オペ 案件の選考進行に合わせて就業ステータスが動く。打診・エントリー後7日選考が動かないと警告。稼働終了後は待機中に戻すか、連絡が取れない・就業意思なしなら非アクティブへ。 ―

05日次・週次の運用

フローを回す実務は、ほぼタスクボードの上で完結します。見る順番を固定するのがコツです。

DAILY / 朝

タスクボードを上から3ブロック

① スケジュール（本日・明日の確定予定）→ ② 要対応（停滞している依頼／候補停滞／枠未確保／期限超過）→ ③ ステータス看板。担当者フィルタは既定で「自分」なので、チーム全体を見るときは「全員」に切り替える。

DAILY / 判断

赤と黄で動きを変える

赤＝自分たちが手を動かす。黄＝企業への催促を1本入れて記録を残す。催促した事実は対応メモに残すと停滞カウントの起点がリセットされます。

WEEKLY

棚卸しする3点

完了確認中に溜まった依頼（手動でしか完了しない）／保険手続き・喪失の未処理／メンバー別の担当件数の偏り。ダッシュボード下部の担当状況表で確認します。

停滞が「消える操作」と「消えない操作」

停滞日数は案件が実質的に進んだ最後の日時から数えます。ここを取り違えて「担当を付け替えたのに警告が消えない」となりがちなので、チームで共通認識にしておきます。

消える（進行として扱われる）消えない（進行ではない）
  • 対応メモの追加・操作にともなう履歴の記録
  • 求人媒体の掲載ステータス変更／受注条件の変更
  • 候補の追加・選考ステータス変更（打診・提案・見学・決定・見送り）
  • 確定スタッフの情報更新（時給・勤務日数・保険）
  • 企業側の操作（受入回答・条件変更見積もりの回答・派遣必須情報の登録）
  • 担当営業・担当オペレーターの変更
  • 企業側窓口（ご担当者・連絡先）の変更
  • 企業が依頼詳細を開いた（既読になった）
  • 履歴が残らない編集・一覧やボードの閲覧

日数はすべて変更できます。ステータス別／候補フェーズ別／枠未確保／期限超過の猶予は システム → コパン詳細設定 → 依頼管理、仮登録ヒアリング未設定と打診中未動きは 同 → スタッフ タブ。数値を保存すれば即時反映されます。この資料の日数は現在の既定値です。

SHOWJIN GROWTH DATA PLATFORM / ENGINEERING CONCEPT

広告・広報・求人・稼働・給与を
ひとつのデータでつなぐ。

Google Analytics、SNS、hanabacca、花JOB、ハナワク、Copain、Showcaseを横断し、「誰が、どこで知り、どの経路を通り、どのサービスを使い、最終的にどれだけ働き・稼いだか」まで追跡できるデータ基盤を構築する。

Engineering Concept Draft / 株式会社笑人 / 2026.09
01 / PURPOSE

目的は「アクセス解析」ではない。

このシステムの目的は、PV・フォロワー・広告クリックを一覧化することではない。広告・広報・メディア活動が、実際の登録・応募・面談・受注・稼働・給与・粗利へどうつながったかを一気通貫で可視化し、その結果から次の施策を自動的に改善することである。

「何が伸びたか」ではなく、
「何が人を動かし、会社と働く人にどんな結果を生んだか」を見る。
02 / BUSINESS QUESTIONS

最終的に答えられるようにしたい問い。

媒体・企画どの記事、Reel、YouTube、広告、検索キーワードが登録や稼働につながったか。
サービス横断hanabaccaで知った人が、その後 花JOB・ハナワク・Copainをどう利用したか。
人単位あるユーザーが笑人と最初に接点を持ってから、どのサービスで何回働いたか。
給与・経済価値その人が笑人グループのサービス経由で実際にどれだけ給与・報酬を得たか。
平均値流入元・媒体・テーマ別に、一人当たり平均稼働回数・平均給与・平均LTVがどう違うか。
企業側どの媒体・企画から来た企業が求人依頼・派遣依頼・受注・粗利につながったか。
PDCA過去に似た施策を行った時、何が成功し何が失敗したか。次は何を変えるべきか。
予算配分次月の広告費・取材・制作工数を、どのテーマ・媒体に寄せるべきか。

05 / ID DESIGN

最重要：人・企業・流入を同じID体系でつなぐ。

データが集まっても、同一人物をサービス間で接続できなければ経営分析には使えない。そのため、登録前の匿名アクセスから、登録後の人物IDまでを段階的に接続する。

anonymous_id       // Cookie等の匿名識別子
session_id         // Web訪問単位
touchpoint_id      // SNS / 記事 / 広告 / 検索等の接点
campaign_id        // 施策・キャンペーン
theme_id           // 「花業界の給与」等の企画テーマ
content_id         // 記事・動画・投稿単位

lead_id            // 登録・問い合わせ時に発行
service_user_id    // 花JOB / ハナワク / Copain 各サービスID
unified_person_id  // 笑人グループ横断の人物ID
company_id         // 法人/企業統合ID
job_id             // 求人・案件ID
work_id            // 稼働実績ID
payroll_id         // 給与/報酬実績ID
revenue_id         // 売上実績ID
理想： ログイン・登録後に anonymous_id と unified_person_id を安全に接続し、「登録前に何を見ていたか」から「登録後にどれだけ働いたか」までつなげる。

07 / ECONOMIC VALUE

「誰が、どの経路で、どれだけ稼いだか」を出す。

この基盤の面白さは、コンバージョンを「登録」で止めず、働く人が実際に得た経済価値まで追えることにある。

PERSON個人累計給与・報酬笑人グループ内の対象サービス経由で、ある人が累計いくら得たか。
ACQUISITION流入元別 平均給与hanabacca、Instagram、Google検索、広告などの流入元ごとに平均を比較。
THEMEテーマ別 経済価値「給与」「転職」「母の日」等、どの企画から来た人が長く働いているか。
SERVICEサービス横断収入ハナワク → Copain等、複数サービスを使った人の累計実績。
LTV一人当たりLTV会社粗利だけでなく、本人の累計給与・稼働回数・継続月数も併記。
SOCIETAL VALUE働く機会を生んだ金額メディア・サービスが最終的にどれだけの雇用・所得機会を作ったか。
重要：「笑人が直接支給した給与」と「花JOB等で紹介先企業が支給する給与」は混在させない。
実績支給額 / 推定年収 / 求人票上の給与条件 を別フィールド・別指標として管理する。

09 / PDCA ENGINE

PDCAを「担当者の記憶」ではなく、システムに残す。

過去の施策・仮説・結果・改善内容をすべて履歴化し、次回のPlanとActionを過去傾向からAIが提案する。

PLAN仮説誰に、何を、どの媒体で、なぜ届けるか。期待KPIと予算を保存。
DO実行投稿・広告・記事・取材・LP等の実行履歴をTheme ID / Campaign IDで統合。
CHECK結果リーチ → 流入 → 登録 → 面談 → 稼働 → 給与 → 粗利まで自動評価。
ACT改善成功・失敗要因を記録。次の予算、企画、対象、クリエイティブを提案。

10 / AI LEARNING LOOP

過去傾向から「次に何をするか」を継続提案する。

AIには単月データだけを渡さず、過去のPDCA履歴・季節性・媒体別傾向・テーマ別成果・求人需給・稼働実績まで参照させる。

Plan提案例「昨年10〜11月は“繁忙期×短期勤務”テーマがハナワク登録率と稼働率の両方で高かった。前年より企業案件が増えているため、今年は9月末から取材・動画を前倒しする。」
Action提案例「Instagramはリーチが高いが稼働率が低い。一方YouTube接触者は登録数は少ないが3か月継続率が高い。次回はInstagramからYouTube/記事への中間導線を増やす。」

13 / PRIVACY & SECURITY

個人単位で追えるからこそ、分析用データと個人情報を分離する。

GA4等の外部分析基盤へ、氏名・メール・電話番号などを送らない。外部分析では自社発行の非識別IDを使用し、本人情報との対応表はShowcase側の権限制御された領域で保持する。
分析基盤unified_person_id、属性カテゴリ、行動、稼働、集計値。原則として分析に不要なPIIを持たない。
Showcase個人情報領域氏名、連絡先、契約・給与詳細等。RBAC、監査ログ、閲覧権限を設定。

ダッシュボード表示

  • 経営画面：原則集計値。必要時のみ権限者が個別ドリルダウン。
  • 広告・広報担当：個人名・個別給与を見せず、流入元別平均・分布・LTV等で評価。
  • 人事・給与担当：業務上必要な給与詳細のみアクセス。
  • すべての個人詳細参照・エクスポートを監査ログへ保存。
14 / IMPLEMENTATION PRIORITY

実装優先順位。

STEP 1｜計測設計を統一Theme ID / Content ID / Campaign ID / UTM / イベント命名規則 / サービス横断ID方針を確定。
STEP 2｜外部データを自動取得GA4・Search Console・YouTube・Instagram等をConnector化し、日次で統合DBへ保存。
STEP 3｜ShowcaseのJourney Eventを整備登録・応募・面談・決定・稼働・給与・売上・粗利のイベントを共通形式で記録。
STEP 4｜Identity Mapを接続anonymous_id → lead_id → service_user_id → unified_person_id を安全に結合。
STEP 5｜経路・LTV・給与分析First / Last / Assist / Multi-touch と、平均給与・継続・粗利まで算出。
STEP 6｜PDCA EnginePlan・Do・Check・Actを履歴化し、過去傾向を踏まえたAI提案を開始。
15 / COMPLETION CONDITIONS

この基盤の「完成」の定義。

1主要サイト・SNSのデータが日次で自動取得される。
2各コンテンツがTheme ID / Content IDで横断管理される。
3登録前の流入から登録後の稼働までを人物単位で接続できる。
4媒体・テーマ別に登録率、稼働率、平均給与、LTV、粗利を比較できる。
5PDCAの仮説・結果・改善・意思決定理由が履歴として残る。
6AIが過去施策を参照し、次のPlan / Action案を継続提示できる。
7AI提案の採否と、その後の結果も保存され、提案精度を検証できる。
8個人情報・給与情報は適切に分離・権限制御・監査される。
16 / NORTH STAR

最終的に作りたいもの。

「広告を出したら何人来たか」ではなく、

「どの発信・取材・SNS・広告が人との最初の接点になり、
その人が笑人の中でどんな仕事と出会い、どれだけ働き、どれだけ稼ぎ、
会社にはどれだけの事業価値が生まれたか」までわかる状態。

その履歴を毎月蓄積し、次の施策を過去の成功・失敗から学習して改善し続ける。これは広告分析システムではなく、笑人全体の「集客 → 雇用 → 収益 → 学習」を循環させるGrowth Data Platformとして設計する。

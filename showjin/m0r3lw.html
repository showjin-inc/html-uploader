2. 派遣登録の計測 ① copain.florist 側要作業：広さん

ヘッダー・フッターの「派遣登録」ボタン（リンク先 copain.jp/apply）が押されたら、register_click を送ります。11/3 に追加した応募導線のスニペットと同じ方法です。

入れる場所：WordPress 管理画面 → WPCode → 「スニペットを追加」→ 新規作成
コードタイプ「JavaScript スニペット」／挿入方法「自動挿入」／場所「サイト全体のフッター」／タイトル「派遣登録ボタンのクリック計測」 
/* 派遣登録ボタンのクリック計測（2026-11-09 追加）
 * WPCode：コードタイプ「JavaScript スニペット」／挿入方法「自動挿入」／場所「サイト全体のフッター」
 * copain.jp/apply（派遣登録ページ）へのリンクが押されたら、GA4 に register_click を送る
 */
(function () {
  document.addEventListener('click', function (e) {
    if (typeof gtag !== 'function' || !e.target.closest) return;
    var a = e.target.closest('a[href*="copain.jp/apply"]');
    if (!a) return;
    var loc = a.closest('.header-dialog') ? 'header_menu'
            : a.closest('header') ? 'header'
            : a.closest('.footer-cta') ? 'footer_cta'
            : a.closest('footer') ? 'footer'
            : 'page_body';
    var m = window.location.pathname.match(/^\/job\/(\d+)\/?$/);
    gtag('event', 'register_click', {
      link_location: loc,
      job_id: m ? m[1] : ''
    });
  });
})();

クリック位置の値：header（PCヘッダー）、header_menu（スマホのメニュー内）、footer_cta（ページ下部の大きいバナー）、footer（フッター）。求人ページで押された場合は job_id も記録します。

3. 派遣登録の計測 ② copain.jp 側要作業：copain.jp の開発担当

派遣登録ページ（copain.jp/apply）は受発注管理システムと同じ copain.jp 上にあり、今は GA が入っていません。登録の完了は copain.jp でしか分からないため、こちらにも計測を入れる必要があります。

ファイル名・画面名は実際の構成を確認してから決めてください。以下は「何をどこで送るか」の仕様と見本です。

3-1. GAタグを入れる（/apply 配下の画面だけ）

コパン求人サイトと同じ測定ID（G-X8YLMNBMSL）を使います。こうすると「求人を見た → 登録した」の流れを1つのレポートで追えます。受発注管理のログイン後の画面には入れません。

<!-- Google tag (gtag.js)：派遣登録ページ（/apply 配下）の <head> に入れる -->
<script async src="https://www.googletagmanager.com/gtag/js?id=G-X8YLMNBMSL"></script>
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag(){dataLayer.push(arguments);}
  gtag('js', new Date());
  gtag('config', 'G-X8YLMNBMSL');
</script>

3-2. 「LINEで友だち追加する」のクリック

/apply の画面（LINEボタンがある画面）に入れます。

<script>
  document.addEventListener('click', function (e) {
    var a = e.target.closest && e.target.closest('a[href*="lin.ee"]');
    if (a && typeof gtag === 'function') {
      gtag('event', 'register_line_click');
    }
  });
</script>

3-3. 登録フォームの送信完了

/apply/form の送信が成功した直後に表示する画面だけで1回送ります。

<script>
  if (typeof gtag === 'function') {
    gtag('event', 'register_complete');
  }
</script>
  • 完了画面を再読み込みしても再送しないよう、送信直後だけ出力してください（Laravel なら redirect()->with() のフラッシュ値があるときだけ出す、など）。
  • 画面遷移せずに JavaScript で送信している作りなら、送信成功時の処理の中で gtag('event', 'register_complete') を呼んでください。
  • 氏名・電話番号・メールアドレスなどの個人情報は、GA に送らないでください（GAの規約で禁止されています）。
  • copain.florist から移動すると、URL の末尾に ?_gl=… が付きます。copain.jp/apply?_gl=test を開いて、エラーにならないことを確認してください。

これで「派遣登録数 ＝ register_complete（フォーム）＋ register_line_click（LINE経由）」として数えられます。LINE経由の実際の友だち追加数は、LINE公式アカウントの管理画面の数字と突き合わせてください。

4. 応募フォームのエラー確認とテスト（⑥）

応募フォーム（/job-entry/）では、入力エラーが出ると job_apply_error が送られ、どの項目でエラーになったかも記録されています。今日その項目をGAで見られるように登録しました。登録前の2件は項目まで分かりませんが、今日以降の分は分かります。

テスト手順（PCで約15分）

  1. Chrome で tagassistant.google.com を開き、https://copain.florist/job-entry/?job_id=593 を入力して「接続」。別タブで応募フォームが開きます。
  2. 別のタブで GA を開き、管理 → DebugView を表示しておきます（自分のテストだけがリアルタイムで流れます）。
  3. 空欄テスト：何も入れずに同意にチェックして「送信」。job_apply_error が出て、error_fields にエラー項目が並べばOK。
  4. 形式エラーテスト：メールに test、電話番号に文字を入れて送信。error_fields に email・tel が出るか確認。
  5. 生年月日：カレンダーで年を選べるか、エラー後にもう一度カレンダーが開くかを確認。
  6. ここで止めれば、実際の応募は送られません。

スマホでのテスト（重要）

求人ページへの訪問の多くは、LINEアプリなどから開かれています。LINEで自分に求人URLを送り、LINEの中で開いて、次の点を確認してください。

  • 生年月日のカレンダーが開くか、年を選べるか
  • 同意にチェックすると送信ボタンが押せるようになるか
  • 入力欄が画面からはみ出していないか、キーボードでボタンが隠れないか

iPhone（Safari・LINE）と Android（Chrome・LINE）の4通りで確認するのが理想です。

送信完了のテスト（実際に応募が届きます）

  • 事前に応募の受付担当へ「テスト送信します」と伝え、氏名を「テスト 送信」にして送信します。
  • DebugView に job_apply_complete が1回だけ出ればOK。完了画面を再読み込みしても、キーイベントは1回のままのはずです。

毎週の見方（GA）

  1. 左メニュー「探索」→「自由形式」を新規作成
  2. ディメンションに「応募エラー項目」「応募エラー種別」「求人ID」を追加し、行に入れる
  3. 指標に「イベント数」を入れる
  4. フィルタで「イベント名 ＝ job_apply_error」

同じ項目が何度もエラーになっていれば、その入力欄の説明や形式を見直すのが一番効く改善です。通常のレポートへの反映には24〜48時間かかります。

5. 社内アクセスの除外（固定IPなしの場合）

シークレットウィンドウでも GA には記録されます。しかも開くたびに「新しい人」として数えられるため、新規ユーザー数がかえって増えてしまいます。

PC：Google 公式の拡張機能を入れる（おすすめ）

Chrome ウェブストアで「Google Analytics オプトアウト アドオン（Google 提供）」を社内PCに入れてもらいます。そのブラウザからは GA に一切記録されなくなります。設定は1回、約1分です。

スマホ：社内用の合図URLを開いておく（次の段階）

社員だけが知っているURL（例：copain.florist/?staff=1）を一度開くと、その端末では記録しない仕組みをサイトに入れる方法です。GAタグより先に動かす必要があるため、タグの読み込み順を確認してから実装します。

6. LINE配信などのリンクに目印（UTM）を付ける

LINEアプリ内で開かれた訪問は「どこから来たか」が残らず、GAでは「Direct（直接）」にまとめられてしまいます。リンクの末尾に目印を付けると、配信ごとの効果が分かるようになります。

例：11/4 のLINE配信で麻布十番の求人を送る場合

https://copain.florist/job/593/?utm_source=line&utm_medium=social&utm_campaign=20261104_job593
utm_sourceどこで配ったか：line / instagram / kintone など
utm_medium種類：SNS・LINEは social、メールは email
utm_campaign配信の名前：日付_内容（例 20261104_job593）

結果は GA「集客 → トラフィック獲得」で、表の見出しを「セッションのキャンペーン」に切り替えると見られます。
